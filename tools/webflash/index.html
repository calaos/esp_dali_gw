Board

The two boards look identical. Same size, same pin header, same Pico-DALI2 on top — only the silkscreen under the module tells them apart. An image built for the other one damages nothing, but the board will not boot. If you pick wrong here the flasher stops with not supported when it reads the chip, before it writes anything; it is still the one thing worth checking twice.

The DALI bus needs its own power supply

Read first

The Pico-DALI2 has no DALI bus power supply — it is a transceiver only. An external DALI PSU (16 V, ≤ 250 mA) must be present on the bus or nothing will ever answer.

An unpowered bus is a normal, detectable condition, not a fault: the gateway reports powered: false, blinks the status LED red and keeps running.

Flashing erases the device

The image is written from offset 0x0 and covers the bootloader, the partition table, the app and the configuration area, which comes back blank: Wi-Fi credentials, broker settings, fitting names, groups and scenes all go. The DALI control gear itself is not touched — short addresses, scenes and groups stay programmed in the fittings.

Updating an already-provisioned gateway? Use the OTA upload in its own web UI with esp_dali_gw-<board>.bin from the release instead; that keeps the configuration.

What happens on the first boot

With no Wi-Fi credentials stored, the gateway starts its own access point.
